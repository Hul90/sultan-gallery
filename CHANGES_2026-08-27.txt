SULTAN GALLERY - BUILD FIX 6

Fixed: Sultan Tools sub-tools (Collage, Compressor, Format Converter,
Images-to-PDF, Contact Sheet, Format Analyzer) only showed a small,
hard-capped slice of the Working Folder photos when you opened them,
so tools couldn't be used on every picture in the selected folder.

Root cause: each tool's picker list inside SultanToolsScreen.kt was
artificially truncated with `.take(N)` before being shown, independent
of how many photos were actually selected in the Working Folder:
  - Sultan Photo Collage picker:      capped at 24 photos
  - Sultan Image Compressor picker:   capped at 15 photos
  - Sultan Format Converter picker:   capped at 15 photos
  - Images to PDF Document picker:    capped at 30 photos
  - Sultan Format Analyzer picker:    capped at 60 photos
  - Contact Sheet Generator:          didn't let you pick at all,
                                       silently used only the first 20
                                       photos from the folder

Fix:
  - Removed every artificial `.take(N)` limit from the Collage,
    Compressor, Format Converter, Images-to-PDF, and Format Analyzer
    pickers. They now list every photo/video currently in the
    Working Folder (or your manual selection), exactly like the
    working-folder grid above them.
  - Rebuilt the Contact Sheet Generator as a real picker: it now shows
    every photo in the Working Folder and lets you check which ones go
    on the sheet, capped only at 36 photos per sheet (a real rendering
    limit of one printable index image, not an arbitrary restriction),
    with a running "Selected: X / 36" counter.

No intentional feature removals. Existing Sultan Tools, Quick Panel,
format filter, cached startup and selection workflow are retained.

SULTAN GALLERY - BUILD FIX 5

Fixed two runtime UX bugs reported after installing the APK:

1. Bottom action bar overlapping the system navigation bar in Photo
   Viewer and Video Player.
   - Both screens turn on ImmersiveMode(enabled = true), which draws
     content edge-to-edge (setDecorFitsSystemWindows(window, false)) so
     the transient nav bar can be swiped in over the content. Their
     bottom control bars were not padded for that inset, so the
     buttons sat right underneath the (swiped-in) navigation bar.
   - Fix: added .navigationBarsPadding() to the bottom action Row in
     PhotoViewerScreen.kt and to the bottom controls Column in
     VideoPlayerScreen.kt, so the buttons always stay a nav-bar's
     height above the bottom edge.

2. Screen brightness raised while swiping on a video stayed raised
   on every other screen (photos, albums, etc.) until the whole app
   was closed.
   - VideoPlayerScreen's left-half vertical swipe gesture sets
     brightness directly via `activity.window.attributes.screenBrightness`.
     Since the whole app runs in a single Activity (Compose Navigation),
     that override applied to the Activity window itself and was never
     being reset when leaving the video player, so it kept affecting
     every other screen for the rest of the session.
   - Fix: added a DisposableEffect in VideoPlayerScreen that restores
     `screenBrightness` to `WindowManager.LayoutParams.BRIGHTNESS_OVERRIDE_NONE`
     (system default) the moment the video player screen is left, so the
     brightness change is scoped only to while a video is open.

No intentional feature removals. Existing Sultan Tools, Quick Panel,
format filter, cached startup and selection workflow are retained.
